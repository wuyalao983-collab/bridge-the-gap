# 触发测试集（trigger evals）

用来验证 description 写得够不够准。**"该触发"的十句要能叫起来；"不该触发"的十句要能按住。**
每次改 description，都拿这 20 句过一遍。

## 该触发（should trigger）

覆盖不同说法：明确的 / 隐式的 / 口语的 / 带报错的 / 跨领域的。

| # | 用户原话 | 类型 |
|---|---|---|
| 1 | 我嘴唇有点白，是咋回事？ | 隐式（描述现象） |
| 2 | 这个 `flex: 1` 是啥意思 | 明确（术语） |
| 3 | 我不懂什么是复利 | 明确 |
| 4 | 这行代码报错了：TypeError: cannot read property 'map' of undefined | 报错 |
| 5 | 老板说要做个"用户画像"，这是啥 | 隐式（职场黑话） |
| 6 | 这个数算出来对不上，是不是我哪理解错了 | 隐式（数字对不上） |
| 7 | 合同里写的"不可抗力"到底指什么 | 术语 |
| 8 | 记一下：什么是"灰度发布" | 显式口令 |
| 9 | 孩子作业里这个"光合作用"我不太会，给我讲讲 | 求助 |
| 10 | 啥叫"边际成本"啊 | 口语 |

## 不该触发（should NOT trigger）

重点在"擦边球"——**看着像，其实该干别的**。

| # | 用户原话 | 为什么不触发 |
|---|---|---|
| 1 | 帮我写一份周报 | 纯干活，没有知识盲区 |
| 2 | 把这份 PDF 转成 Word | 纯干活 |
| 3 | 帮我把这些文件按日期重命名 | 纯干活 |
| 4 | 今天天气怎么样 | 查信息，不需要讲通概念 |
| 5 | 我好烦啊，今天不想上班 | 情绪，非知识 |
| 6 | 我要不要换工作？ | 要替他拍板 |
| 7 | 我该不该买这个保险 | 要替他拍板 |
| 8 | 帮我把这段英文翻译一下 | 有"不懂的英文"，但活儿是翻译——**擦边球** |
| 9 | 帮我写个 Python 爬虫 | 涉及不懂的技术，但用户要的是东西——**擦边球** |
| 10 | 你好 | 打招呼 |

> 第 8、9 条是**最有价值的反例**：它们含"不懂"的成分，但用户要的是**结果**，不是**讲通**。
> 这种情况下，skill 要么不触发；要么触发了就**一句话退场**，别硬拆知识链。

## 怎么用

1. 在**新会话**里逐条把原话打进去（一次一条，别混着）。
2. 看它**有没有加载这个 skill**。最省事的验证：直接问一句「**你刚才用了哪个 skill？**」
3. 记录：该触发的漏了几条？不该触发的误了几条？
4. 漏触发 → 把 description 写得更宽更"厚脸皮"；误触发 → 补 "不用于……"。
