# 触发测试集（用来验 description 灵不灵）

改完 `SKILL.md` 顶部的 `description` 之后，拿这 20 句过一遍：
- **正例（10 句）**：应该触发 walking-stick（用户抛出了他大概率不懂的东西）。
- **反例（10 句）**：不应该触发（纯干活、闲聊、或要你替他拍板）。

自动嗅探不可能 100% 准。目标是：正例尽量都上，反例尽量都不上；误触发了也能干净退场（见 SKILL.md「没叫对怎么办」）。

## 正例（应触发）

1. 我嘴唇有点白，是咋回事？
2. 这个 flex: 1 是啥意思？
3. 这行代码报错：Cannot read property 'map' of undefined
4. 老板说要做个"用户画像"，这是啥
5. 什么是复利啊
6. 我的电脑风扇一直响正常吗
7. 这个 API 是干啥的
8. 股票里的"做空"是什么意思
9. 为什么面包放久了会发霉
10. 医生说我"缺铁性贫血"，严重吗（-> 走医疗红线，给方向不留结论）

## 反例（不应触发）

1. 帮我把这个 PDF 转成 Word
2. 今天天气怎么样
3. 帮我写个周报
4. 你觉得我该不该辞职
5. 把这个表格里的数字加总一下
6. 帮我订个明天的闹钟
7. 给我讲个笑话
8. 把这段代码格式化一下
9. 帮我回复一下这个邮件
10. 周末去哪玩比较好（-> 要替他拍板，退场）

## 怎么用

把这些句子逐条喂给装了 walking-stick 的 AI，看它上不上、上讲不讲人话、讲完收不收。
哪里漏了 / 误了，回头调 `description` 或「没叫对怎么办」的退场话术。
